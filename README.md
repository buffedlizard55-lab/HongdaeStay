## Itineraries

Ten of them. They differ mainly in how far you travel; two never use public transport at all. ## Clusters

Each day sits inside one cluster so that walking, not transferring, joins the stops.

| Cluster | Notes |
|---|---|
| **Hongdae core** | Everything walkable from the hotel — Hongik Univ. Station exits 1/3/6/8/9. No subway needed. |
| **Yeonnam-dong** | North of the hotel along Gyeongui Line Forest Park. Hongik Univ. Exit 3 then 380–840 m on foot. |
| **Sangsu / Hapjeong** | South-west of the hotel. Walkable in 15–25 min along Wausan-ro / Yanghwa-ro, or one stop on Line 2/6. |
| **Sinchon** | One stop east on Line 2 (Hongik Univ. → Sinchon), or ~20 min walk. |
| **World Cup Park / Sangam** | Line 6 from Hapjeong — World Cup Stadium / Mangwon. Short hop, one cluster for a whole day. |
| **Ticketed outings (outside Mapo)** | Only used for dated, confirmed shows. Each is a single-destination evening or half-day. |

## Building the site

The page is data-driven (`data.js` + `app.js`) but is **pre-rendered** so it is
never blank if JavaScript fails or is disabled.

```bash
npm install jsdom
node build.js
```

`build.js` runs `data.js` and `app.js` in jsdom, writes the fully rendered
markup into `index.html`, mirrors the site into `docs/`, and **fails the build**
if any content region renders empty. Edit `index.template.html` (structure) or
`data.js` (content) — never `index.html` directly, it is generated.

`itineraries.md` and the three tables in this README are generated from
`data.js` too:

```bash
node gen-md.js     # regenerates itineraries.md
node gen-readme.js # regenerates the itinerary / inventory / flags tables here
```

Run all three (build + generators) after any edit to `data.js`.
